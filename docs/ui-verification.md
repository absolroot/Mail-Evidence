## 1.5.3 첨부 목록과 원본 위치

첨부 표에는 파일명, MIME 유형, 크기만 표시합니다. 선택한 첨부 아래에서 바이트 형태가 명시된 SHA-256을 읽고 복사할 수 있습니다. 판독에 제약이 있으면 아래에 사유를 표시합니다. MIME 파트와 인코딩 범위, MSG 저장소·스트림 경로, PST·OST의 첨부 NID와 MAPI 태그는 **원본 위치**를 펼쳐 확인합니다.

**속성 바이트 보기**에서는 원본 이름, MAPI 태그, 첨부 식별자를 먼저 표시합니다. 경로와 NID 등은 항목별로 펼쳐 읽고 복사할 수 있습니다. 원본 파일 SHA-256과 첨부 데이터 SHA-256에는 각각의 기준을 표시합니다.

PST의 11개 첨부를 표에서 비교하고, 행을 바꿀 때 전체 해시와 NID가 갱신되는지 확인했습니다. 실제 PST·OST 속성 바이트와 MSG 스트림 바이트를 독립 판독 기준과 대조하고, 원본 보기에서 선택한 첨부로 복귀했습니다. 좁은 MSG 창과 밝은·어두운 화면을 Windows 175%에서 확인했습니다. 콘솔 검증 28개, 포맷별 WPF FlowSmoke와 작업공간 lint를 통과했습니다.

시작 화면을 확인한 Windows x64 EXE의 제품 버전은 1.5.3입니다. SHA-256은 `2754908b47060fbd2bf428095a1ac8245dd0ace26486a5a58dae354e53bc0b7b`입니다.

## 1.5.5 본문에서 첨부 확인

제보에 나온 합성 EML을 확인했습니다. 본문처럼 보였던 첫 줄은 첨부 버튼의 잘린 파일명이었습니다. 본문 위 버튼은 종이클립과 첨부 개수를 먼저 표시합니다. 첨부가 하나면 파일명을 함께 표시하고, 길면 끝을 줄입니다. 버튼에서 첨부 목록을 열 수 있습니다. 첨부 탭에서 메일을 바꿀 때 첨부가 있는 메일은 탭을 유지하고, 첨부가 없는 메일은 본문을 엽니다.

Windows 175%에서 같은 샘플과 이름이 같은 첨부 두 개, 무첨부 메일을 밝은·어두운 테마로 확인했습니다. 두 테마에서 기존 EML·MBOX FlowSmoke도 통과했습니다. 시스템 대화상자에서 저장한 첨부의 해시와 검색 결과 내보내기 범위를 확인했습니다. 작업공간 lint를 통과했고 Windows x64 단일 실행 파일에서 해당 EML의 분석 시작 창을 확인했습니다.

## 1.5.6 제목 표시줄의 MAIL 아이콘

16px ICO의 L 세로 획은 이미 1px이었습니다. 작은 아이콘 계열에서 굵은 획이 남아 있던 20·24·28px에 1px 세로 획을 적용했습니다. 256px 원본의 L은 최초 MAIL 도안의 폭과 일치합니다. 32–256px ICO 프레임은 이전 버전과 바이트가 일치합니다.

새 EXE의 ICO 프레임 12개와 WPF 창 자원을 대조했습니다. Windows 175%에서 실제 실행 창이 읽은 28px 아이콘의 L 세로 획은 1px입니다. 밝은·어두운 배경의 프레임을 확인했고 작업공간 lint를 통과했습니다.

## 일상 메일 샘플 30통

2026년 11월 24일. 기존 합성 메일 16통에 14통을 추가했습니다. EML 30개와 MBOX에서 제목, 메시지 ID, 참조 헤더, MIME 구조와 첨부 내용이 일치합니다. 기존 EML 16개는 SHA-256이 같고 기존 MBOX는 그대로 열 수 있습니다.

WPF에서 EML과 MBOX를 각각 열어 30통이 표시되는 것을 확인했습니다. HTML 추출 텍스트, 두 PNG의 SHA-256, 인라인과 일반 첨부로 들어간 동일 JPEG, 장터 대화의 답장 4통과 갈라진 답장 열기, 독서 모임의 이전 메일 3통을 확인했습니다. 첨부파일 미리보기가 있는 빌드에서 뉴스레터 포스터 PNG도 열었습니다.
